# 套餐规划引擎 · 可重复离线演示（2026-10-14 升级版）

以下演示全部使用 `demo` 子命令离线运行（内置演示数据，结构与麦当劳 MCP 真实返回兼容，
数值非实时），**不需要 MCD_MCP_TOKEN**，可随时重复执行。每个演示下方注明它验证的约束。

对应的自动化断言见 `tests/test_planner_demos.py`（同一场景，CI 可重复）。

```bash
cd burger-quest
python -m burger_quest demo "<需求>"
```

---

## 演示 A：用户原话 —— 多条件综合（预算/口味/人数/蛋白/少饮料）

```bash
python -m burger_quest demo "预算 35 元，想吃辣，两个人，希望尽量高蛋白，不想点太多饮料"
```

实测输出（关键部分）：

```text
【方案对比】按推荐顺序排列（最多 3 个可比较方案；总价均为 calculate-price 权威结果）：
  👉 [1] 2 人分享阵型·已叠券 —— 麦辣鸡腿堡 + 麦辣鸡翅（2块）（¥25.00，预算内）
        ✅ 口味命中：麦辣鸡腿堡、麦辣鸡翅（2块）
        ✅ 优惠券已省 ¥8.00（权威核验）
        ✅ 预算内，剩余 ¥10.00
        ✅ 整餐热量 约 840 千卡
        ✅ 蛋白质 41g 达标（偏好 ≥25g）
        ✅ 饮料 0 份，符合少饮偏好（≤1）
        ⚠️ 不完全符合：主食 1 份，少于 2 人（轻量分享，可能吃不饱）
     [2] 2 人分享阵型·已叠券 —— 双层吉士堡×2 + 麦辣鸡翅（2块）（¥33.00，预算内）
        ✅ 主食 2 份，够 2 人分食 …… ✅ 蛋白质 62g 达标
     [3] 2 人分享阵型 —— 双层吉士堡 + 麦辣鸡翅（2块）（¥25.00，预算内）
        ✅ 蛋白质 39g 达标 …… ⚠️ 不完全符合：主食 1 份，少于 2 人
```

验证的约束：

| # | 约束 | 演示中的体现 |
| --- | --- | --- |
| 1 | 商品只来自真实查询/演示数据 | 餐品均来自演示菜单（DEMO-001），输出标注「演示数据」 |
| 2 | 价格缺失不入组合 | 全部餐品均有价（无价餐品在别的用例中验证会被排除） |
| 3 | 总价来自 calculate-price | 每个方案标注「总价以 calculate-price 为准」；¥25 = 33 − 8 券 |
| 4 | 券只来自真实券池 | 两张券均来自演示券池（门店券 + 我的券） |
| 5 | 不默认优惠可叠加 | ¥8 减免是权威核验结果；若 authority 不认会备注（见测试） |
| 6 | 营养偏好用真实数据 | 蛋白质 41g 由真实营养数据汇总；无数据餐品会被标注 |
| 7 | 不自行补充条件 | 未提供用餐方式时明确提示「默认到店自取」 |
| 8 | 排序 + 符合/不完全符合说明 | 3 个方案按推荐序排列，逐条 ✅/⚠️ |
| 9 | 无可行情景可解释失败 | 见演示 D |
| 10 | 整数分精确金额 | 输出全部由「分」换算展示，无浮点误差 |
| 11 | RPG 不改变数字 | 剧情文案与结算数字分离（测试断言深拷贝不变） |

## 演示 B：超预算参考 —— 最接近的真实价格，明确标注不隐瞒

```bash
python -m burger_quest demo "预算12块，想吃辣"
```

实测输出（关键部分）：

```text
【推荐装备】
  ⚔️ 双倍干酪壁垒 —— 双层吉士堡（¥13.00）
【价格结算】
  应付总价：¥13.00（calculate-price 权威结果）
  超出预算：¥1.00
⚠️ 不完全符合：超出预算 ¥1.00
⚠️ 不完全符合：口味偏好（辣味）未被任何餐品命中
```

验证的约束：超预算时给出**最接近的真实价格方案**作参考（¥13 vs 预算 ¥12），
明确标注「超出预算 ¥1.00」与未命中的口味——不编造一个 ¥12 内的「成功」套餐，
也不把价格篡改成预算值。

## 演示 C：品类硬避免 —— 「不要饮料」

```bash
python -m burger_quest demo "不要饮料，预算20"
```

实测输出（关键部分）：

```text
  👉 [1] 省钱精算阵型 —— 双层吉士堡（¥13.00，预算内）
        ✅ 预算内，剩余 ¥7.00
        ✅ 整餐热量 约 450 千卡
```

验证的约束：候选组合**完全不含饮品**（硬避免品类出局）；预算内、价格经权威核验。
对比演示 A 的「不想点太多饮料」（软上限：允许 ≤1 份并在理由中明示），
两种饮料偏好语义不同、都被正确识别（解析层 11 条用例覆盖）。

## 演示 D：无可行解 —— 可解释失败 + 调整建议

```bash
python -m burger_quest demo "预算5块，想吃汉堡"
```

实测输出（关键部分）：

```text
⚠️ 没有组合能落在 ¥5.00 预算内（2 个候选组合因估算价超出预算被跳过，
   其余逐一用权威价格核验；未编造任何价格）。可尝试：适当提高预算，或减少人数/品类要求
❌ 未生成方案。原因见上方提示——引擎不会编造餐品、价格或优惠。
```

验证的约束：预算远低于任何真实组合时，**明确失败并说明原因**，
给出「提高预算 / 减少条件」的可操作建议，不输出虚假成功方案。
